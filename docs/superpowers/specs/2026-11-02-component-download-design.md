# 组件代理下载设计

- 日期：2026-11-02
- 状态：已实现，仓库全量门禁与浏览器预览验收通过；Windows 真机与企业代理实际大文件下载待验收。
- 范围：在已有组件更新检查基础上下载官方文件，不安装、不解压、不修改现有组件。
- 用户已确认：应用内置下载，默认保存到系统下载目录下的 `CodexHelper` 文件夹。

## 目标与交互

有更新时，在组件行显示“通过代理下载”。Windows 桌面端下载清单指定的 x64 MSIX；Codex CLI 根据本机架构选择 Windows `.exe.zip` 或 macOS `.tar.gz`。显示已下载字节、总大小（服务器提供时）、取消按钮，完成后展示绝对路径。一次只运行一个下载；另一个组件等待当前任务结束。失败可重试；取消清理临时文件。

下载目录通过系统 API 解析，不能假设目录名为英文。目录不可用时返回错误；已有同名文件保留，新文件自动加序号。只在完整下载成功后生成最终文件。首版不支持断点续传、自动安装、解压、后台恢复或 macOS 桌面端下载。

## 方案

采用现有 Rust / reqwest 网络栈在应用内流式下载，复用 TLS 和代理能力；进度通过 Tauri Channel 返回前端。另一方案是调用系统 curl，但会增加外部程序依赖和跨平台进度解析，因此选择内置方案。用户已同意按此方案直接推进。

## 下载来源与网络约束

- 前端只提交组件、已展示的目标版本和任务 ID，不提交任意 URL 或磁盘路径。
- 桌面端重新读取官方发布清单，要求版本仍与目标版本一致；沿用下载 URL 白名单。
- CLI 校验稳定版版本格式，再从固定的 `openai/codex/releases/download/rust-v<版本>/<官方文件名>` 构造文件地址，不下载 release HTML 页面。
- 下载仅允许 Manager 状态为代理运行中；Legacy 与 Secure 均不回退直连，也不接管端口上的外部代理。
- 每跳重定向都显式检查 HTTPS、主机与路径，不允许降级 HTTP、凭据地址、任意主机或无限跳转。GitHub 官方文件分发只放行 `release-assets.githubusercontent.com` 和 `objects.githubusercontent.com`，并将其加入本地 SOCKS5 分流规则；服务端白名单若拒绝则展示失败，不绕过。
- 不携带网关 Key、Cookie 或用户凭据，不记录带签名参数的下载 URL。
- 使用 15 秒连接超时、60 秒读取超时、2 小时总时限和 2 GiB 文件上限；不沿用检查接口的 15 秒整请求超时。

## 模块边界

- `helper-core::component_downloads`：版本与平台选择、URL 约束、代理客户端、流式写文件、长度检查、取消、单任务互斥、完成文件发布。
- Tauri `downloads.rs`：读取 Manager 快照、解析系统下载目录、调用核心、转发进度与取消。
- `componentdownload.ts`：下载状态与展示的纯函数；`componentpanel.ts`：按钮、进度和路径；`main.ts`：生命周期编排。

## 验证

覆盖下载经过代理、未就绪零出站、跨域重定向拒绝、官方重定向允许、超限/截断失败、取消后无成品或临时文件、同名文件不覆盖、单任务互斥与完成后可重试、平台/架构选择，以及前端取消与失败状态。运行仓库门禁；Windows 真实安装环境、实际企业代理的分发域名白名单验收须单独注明。

## 实施结果与保证边界

- 2026-11-02，`scripts/gate.sh` 通过：Rust 570 项通过、1 项既有测试忽略；前端 51 项通过；Clippy、格式、macOS 编译、Windows 目标编译、类型检查和生产构建通过。
- ego-browser 预览验证：开始、进度、取消、重试完成、完成版本与路径、失败提示、代理未运行时禁用下载；预览不写入用户下载目录。
- 独立只读评审覆盖全部改动，没有发现需要修复的问题。
- 文件同步写入单个网络分块，NamedTempFile 全程持有句柄，避免 Windows 取消时尚有异步磁盘任务持有文件；网络等待仍为异步。
- 未知长度响应以 HTTP 正常结束为完成，不做归档结构或校验和验证；有 Content-Length 时必须精确匹配。两种路径都经 TLS，不声称提供校验和级完整性保证。
- 取消与最终保存同时发生时可能以已完成结束，界面以真实结果为准。Windows 真机句柄清理、真实签名 CDN 文件及磁盘满故障尚未实测。
